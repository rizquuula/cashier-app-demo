# Brainstorming Skill

When the user asks to brainstorm, explore ideas, research, or think creatively about a problem, follow this structured approach:

## Mindset

- Be curious, open, and divergent first — generate many ideas before converging
- Default to **AI-ask first**: before searching the web or asking the user, reason through the problem yourself based on what you know
- Frame everything as hypotheses to be tested, not conclusions
- Separate idea generation from evaluation (don't critique during generation)

## Workflow

### 1. Internal Reasoning (AI-ask first)
Before reaching for external tools, use your own knowledge to:
- Identify the core problem or question
- Surface relevant patterns, analogies, or prior art you know
- Generate 3-5 initial directions or ideas
- State what you're uncertain about

### 2. Web Search (when needed)
Use web search to:
- Research existing solutions, libraries, or approaches
- Find best practices, benchmarks, or case studies
- Validate or challenge your assumptions
- Discover what others have tried in similar scenarios
- Search for **current** information (specify the current year)

### 3. Ask the User (targeted questions)
When you hit genuine ambiguity or need direction, ask:
- **Clarifying questions** — narrow the scope
- **Preference questions** — which direction resonates?
- **Constraint questions** — what must not be broken?
- **Priority questions** — what matters most?
- Offer concrete options with tradeoffs, not open-ended "what do you want?"

### 4. Synthesize
- Summarize findings in a structured way
- Present 2-3 distinct options with pros/cons
- Flag open questions and suggested next steps
- Recommend a path forward if clear enough

## Techniques to Use

- **SCAMPER** (Substitute, Combine, Adapt, Modify, Put to other uses, Eliminate, Reverse)
- **First principles thinking** — break down to fundamentals, rebuild
- **Reverse brainstorming** — how would you cause the opposite problem?
- **Analogical thinking** — what do similar domains do?
- **Constraint expansion** — what if budget/time/tech weren't issues?
- **Minimum Viable Idea** — what's the smallest version worth testing?

## When to Switch Modes

- If the problem is well-understood → transition to **planning** or direct execution
- If the user says "let's go with that" → stop brainstorming and start executing
- Always end with a clear **next action** so the session doesn't stall
